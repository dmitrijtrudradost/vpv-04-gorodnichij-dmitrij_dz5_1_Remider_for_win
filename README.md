# Напоминалка для Windows 11

Версия 2.2  Remider_for_win

Приложение на Python для создания напоминаний с уведомлениями. Все данные хранятся
в локальной базе SQLite3, уведомления приходят даже когда окно свёрнуто или закрыто
в системный трей. С версии 2.0 поверх одиночных напоминаний добавлен слой
«Процессы»: многошаговые сценарии с ветками, зависимостями и эскалацией.
В 2.1 у шагов видно и можно править расписание уведомлений. В 2.2 появилось
произвольное «Отложить» и визуальный конструктор пользовательских процессов.

## История версий

| Версия | Содержание |
| --- | --- |
| 1.1 | Одиночные напоминания, календарь со стрелками месяца/года, постоянные уведомления, трей |
| 2.0 | Вкладка «Процессы», шаблоны ЭДО-договор и Охрана объекта, эскалация, блокирующие чек-листы |
| 2.1 | Колонка «Уведомления» у шагов, правка расписания эскалации, граница «уведомлять до» (по умолчанию 18:00) |
| 2.2 | «Отложить» на дату/время, +45 мин / +1 час, конструктор своих процессов, связи шагов |

## Возможности

- Добавление напоминаний с заголовком, описанием и временем срабатывания
- Дата выбирается в выпадающем календаре, время — стрелками часов, минут и секунд
- Уведомление приходит сразу двумя путями: системным баннером Windows 11 и своим
  окном поверх всех окон. Ни то, ни другое не закрывается само
- Статусы: «Ожидает», «Готово», «Просрочено», «Отменено»
- Автоматический перевод в «Просрочено» через минуту после пропущенного времени
- Фильтр списка по статусу
- Отметка «Готово» / «Отменено», удаление с подтверждением
- Кнопки быстрой установки времени: +1, +5, +15, +30, +45 минут и +1 час
- Работа в системном трее: закрытие окна не останавливает напоминания
- Отложить напоминание: на 5 минут или на выбранную дату и время — из всплывающего окна и из списка (одиночные и шаги процесса)
- Копирование и вставка (Ctrl+C / Ctrl+V) в полях форм
- Вкладка «Процессы»: дерево процесс → ветка → шаг, создание по шаблону
- Встроенные шаблоны «ЭДО-договор» и «Охрана объекта»
- Конструктор процессов: свои шаблоны (ветки, шаги, связи, чек-листы, эскалация) без правки встроенных; копирование шагов, несколько входящих зависимостей, правка сохранённого шаблона
- Эскалация шагов ожидания: через 2 часа, затем в 09:00 следующего рабочего дня, далее каждые 3 часа в рабочие часы
- Расписание уведомлений шага видно в дереве и правится по двойному клику или кнопке: первое ожидание, время повтора, интервал и граница «уведомлять до»
- Уведомления процесса по умолчанию только в пн–пт с 09:00 до 18:00; границу 18:00 можно сменить. Одиночные напоминания по-прежнему на любое время суток
- Блокирующий чек-лист: шаг нельзя закрыть, пока не отмечены все пункты
- Отложенная ветка охраны активируется за 3 дня до даты окончания услуг

## Установка и запуск

Пошаговая инструкция для Windows 10 — в [INSTALL.md](INSTALL.md)
(Python, pip, автозапуск при входе в систему).
Обновление уже установленной **2.1 → 2.2** на другом компьютере —
в [UPDATE-2.2.md](UPDATE-2.2.md) (архив релиза, база `reminders.db` не трогается).

Кратко: `pip install -r requirements.txt`, затем `python main.py`.
Первый запуск создаёт `reminders.db` рядом с программой. База версий 1.1–2.1
открывается без ручных действий: таблицы процессов, колонка `notify_until`
и таблица `process_templates` добавляются при старте.

### Схема таблицы `reminders`

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | INTEGER | Первичный ключ |
| `title` | TEXT | Заголовок |
| `description` | TEXT | Описание |
| `due_time` | TEXT | Время срабатывания, `ГГГГ-ММ-ДД ЧЧ:ММ:СС` |
| `status` | TEXT | Один из четырёх статусов |
| `created_at` | TEXT | Время создания записи |
| `step_id` | INTEGER | Связь с шагом процесса или пусто у одиночного напоминания |

Время хранится строкой в формате `ГГГГ-ММ-ДД ЧЧ:ММ:СС` — такой формат корректно
сравнивается прямо в SQL, без дополнительных преобразований.

### Новые таблицы процессов

`processes`, `branches`, `steps`, `step_checklist_items`, `escalation_rules`,
`process_templates`.
Метаданные шаблона (номер договора, адреса и т. д.) лежат в JSON-поле
`processes.metadata`. У шага поле `notify_until` (ЧЧ:ММ, по умолчанию `18:00`) —
последний допустимый момент уведомления в рабочий день.

Таблица `process_templates`: `id`, `name`, `structure_json`, `created_at`.
Встроенные шаблоны из `templates.py` в неё не копируются. Пользовательский
процесс хранит `template_type` вида `user:{id}`.

| Элемент | Действие |
| --- | --- |
| Поле даты | Клик открывает выпадающий календарь. Прошедшие дни выбрать нельзя |
| Три поля времени | Часы, минуты и секунды, каждое со стрелками вверх-вниз |

**Панель инструментов**

| Кнопка | Действие |
| --- | --- |
| `Обновить` | Перечитать список из базы |
| `Тест уведомления` | Проверить, что уведомления доходят |
| `Отметить готовым` | Статус выбранной записи → «Готово» |
| `Отложить` | Для статуса «Ожидает»: +5 минут или своя дата и время |

| `Удалить` | Удаление выбранной записи с подтверждением |

Двойной клик по строке открывает подробности записи. Строки подсвечиваются по
статусу: ожидающие — синим, готовые — зелёным, просроченные — красным,
отменённые — серым.

**Вкладка «Процессы»**

| Элемент | Действие |
| --- | --- |
| Шаблон | «ЭДО-договор», «Охрана объекта» и сохранённые пользовательские |
| Конструктор процессов | Отдельное окно: ветки, шаги, стрелки-зависимости, чек-лист и эскалация |
| Показать/Скрыть данные договора охраны | Только для шаблона «Охрана объекта»; повторный клик закрывает поля |
| Создать процесс | Разворачивает ветки и шаги шаблона |
| Отметить шаг выполненным | Закрывает выбранный ручной шаг, если нет блокировки |
| Открыть чек-лист | Модальное окно обязательных пунктов |
| Расписание уведомлений | Правка эскалации выбранного шага (то же окно по двойному клику) |
| Колонка «Уведомления» | Сводка правил эскалации; у ручных шагов — тире |
| Колонка «Подробности» | У шага «в ожидании» — ближайшее время срабатывания |

## Как это работает

Фоновый поток раз в секунду проверяет базу: переводит опоздавшие записи в
«Просрочено» и показывает уведомления для тех, чьё время наступило. Поток
намеренно не создаёт окна сам — Tkinter не потокобезопасен, поэтому всплывающие
окна ставятся в очередь, которую разбирает главный поток. Соединение с SQLite
общее для обоих потоков и защищено блокировкой.

### Почему уведомление не исчезает само

Когда наступает время, показываются сразу два уведомления, и это сделано
намеренно.

Системный баннер Windows отправляется с атрибутом `scenario="reminder"` — именно
он заставляет систему держать баннер на экране, пока пользователь сам его не
уберёт. Обычный тост исчез бы через несколько секунд. Выставить этот атрибут
умеет только пакет `windows-toasts`; если его нет, программа переходит на
`winotify`, но тот держит баннер не дольше 25 секунд. Какой способ используется
сейчас, видно в статус-баре справа.

Своё окно поверх всех окон показывается всегда и не имеет таймера автозакрытия —
оно ждёт нажатия «Готово», «Отложить» или «Закрыть». Это страховка: системные
уведомления можно отключить в настройках Windows или заглушить «Фокусировкой
внимания», а окно появится при любых настройках. Если напоминаний накопилось
несколько, окна сдвигаются по диагонали, чтобы не сливаться в одно.

Кнопок на самом баннере нет: интерактивные тосты Windows требуют
зарегистрированного в системе идентификатора приложения (AUMID, то есть ярлыка в
меню «Пуск»), иначе кнопки молча не работают. Поэтому все действия собраны в
своём окне.

### Почему больше не используется win10toast

Первая версия работала через `win10toast`, но он выставить `scenario` не умеет, а
значит не может показать постоянное уведомление. Вдобавок он давно не обновлялся
и на современном окружении просто не импортируется: при `setuptools` версии 81 и
новее падает с `ModuleNotFoundError: No module named 'pkg_resources'`, потому что
этот модуль из setuptools удалён.
